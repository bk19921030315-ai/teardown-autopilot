# teardown-autopilot

一句话描述一台机器，自动做出一个**经过检查、可以交互的 3D 拆解模拟器**。

这是一个 Claude Code 技能（skill）。它把 [teardown](https://github.com/elvarofficial/teardown) 技能的整套流程串起来自动跑完：
找真实数据 → 手算验证 → 建模 → 3D 零件 → 控制台 → 导览动画 → 全面检查 → 可交互网页 →（可选）1080p60 视频 → 报告。

## 怎么用

在 Claude Code 里输入：

```
/teardown-autopilot 做一个汽车雨刮器四连杆机构的模拟器
```

或者直接说"做一个……的模拟器""拆解演示""工作原理 3D 演示"，技能也会自动启用。英文同样可以。

**它会问你一次、停一次：**

1. **开头问一次**：结束时要不要录 1080p60 视频（这个云端环境没有显卡，视频要渲染好几个小时）。没附参考图时，也会提醒你可以附一张。
2. **核对完数据后停一次**：给你看真实尺寸、来源、手算验证，以及它觉得需求里有问题的地方，等你说"继续"或指出要改的数字。

之后一路自动跑完，最后交给你：

- 可离线打开的交互网页（自动导览；点击、拖动、滚轮或按键接管，25 秒没操作自动回到导览；H 隐藏面板，P 显示帧率）
- 每个节拍的静帧和检查报告：碰撞、跳变、标签遮挡、数字和姿态是否一致
- （如果选了）视频和每个节拍的拼图

界面文字跟你提需求的语言一致：用中文问，就是中文界面。

## 写需求的小技巧

一句话就能跑，但多给一点信息，结果会好很多：

- **说具体型号**："某车型的前雨刮"比"雨刮器"好
- **附参考图**：剖面图、照片、说明书截图，直接拖进对话框
- **给已知数字并说明来源**："曲柄长 45 mm（我量的）"
- **说你最想看懂什么**："电机一直朝一个方向转，雨刮为什么会来回摆"

## 安装

- **在这个仓库里开云端会话**：自动加载，什么都不用装。
- **装到自己电脑上的 Claude Code**：把 `.claude/skills/teardown-autopilot/` 整个文件夹复制到 `~/.claude/skills/` 下面。
- 依赖的 `teardown` 技能、Node 包和浏览器，由 `scripts/setup.sh` 在第一次运行时自动准备（需要 Node.js 20+；做视频需要 ffmpeg）。

## 里面有什么

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 整个流程：每一步做什么、什么时候停 |
| `references/` | 各阶段的详细规则：建模、控制台、动画、检查、网页、环境限制、报告模板，以及之前踩过的坑 |
| `scripts/setup.sh` | 安装并准备 teardown |
| `scripts/clearance-template.mjs` | 碰撞检查模板：在整个输入范围内检查每一对运动件 |
| `scripts/continuity.cjs` | 每 0.01 秒采样一次，找画面跳变 |
| `scripts/purity.cjs` | 验证每一帧只由时间决定（乱序重画逐字节一致） |
| `scripts/framediff.py` | 找过渡里的突变帧 |
| `scripts/warmtest.cjs` | 验证着色器预热完整（点按钮时不会卡顿） |
| `scripts/livecheck.cjs` | 验证网页的接管、导览回归、画质分级 |
| `scripts/record.sh` | 可断点续录的 1080p60 视频录制 |
| `examples/` | 做好的范例代码：完整跑完流程的 V8 发动机、起落架的数据建模，新机器直接照着改 |

## 需要知道的

- 云端环境**没有显卡**：一张 1080p 帧要 15 秒左右，30 秒的视频要好几个小时。网页在你自己电脑上的真实帧率，可以加 `?perf` 打开查看。
- 技能会给每个数字标来源：你给的、查到的（附链接）、推算的、估计的、它自己选的（附原因）。不会把估计值说成真实数据。
